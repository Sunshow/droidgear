## Notes

- Channel import for OMP is one shared implementation
  (`droidgear_core::omp_import::prepare_omp_channel_import`) behind the GUI
  `Import Provider from Channel` dialog and the TUI's `i` action, so protocol /
  base-URL / registry inference cannot drift between them.
- Pi channel import still infers in the GUI dialog
  (`src/components/pi/PiImportFromChannelDialog.tsx`) while the TUI does its own
  mapping; unifying it in `droidgear-core` is tracked in `docs/tasks-todo/`.
- Every surface keeps unknown keys: Pi merges over the live `models.json`, OMP
  merges unknown provider/model keys, Hermes keeps unknown YAML sections, Codex
  keeps unknown provider keys.
